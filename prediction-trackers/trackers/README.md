# Prediction trackers

Each folder here is one tracker: `<slug>/tracker.json` is its specification,
reviewed in a pull request, and `<slug>/data.json` is generated by the engine
and read by `prediction.html`. Do not edit `data.json` by hand.

Trackers normally start from a Strapi draft post tagged `prediction-idea`: the
daily intake workflow drafts `tracker.json` and opens a pull request. Merging
that pull request (with `"status": "active"`) turns the tracker on.

`rejected.json` lists Strapi entry ids whose intake pull request was closed
without merging. The intake workflow opens no new pull request for them. To let
an idea through again, remove its id from the list.

## Specification fields

`tracker.schema.json` is the full definition.

| Field | Meaning |
|---|---|
| `slug` | Folder name and page address (`prediction.html?t=<slug>`). Lowercase words joined by `-`. |
| `title` | Short name shown above the question. |
| `status` | `draft` (needs editorial input; not run), `active`, `resolved-yes` or `resolved-no`. |
| `needs_input` | Draft only: what the editor must supply before the tracker can be activated. |
| `strapi.id` | The Strapi entry the idea came from. Stops the same idea being drafted twice. |
| `question` | One yes/no question with a date. |
| `deadline` | `YYYY-MM-DD`. After this date research stops and the tracker waits to be resolved. |
| `resolution.yes` / `.no` / `.source` | What counts as YES and NO, and the source that decides it. |
| `base_rate.p` / `.reasoning` | Starting probability (0.01–0.99) and why. |
| `signals[]` | Types of evidence: `type` (lowercase, `_`-separated), `label`, and `weight` (0–3, in log-odds units; see below). |
| `actors[]` | Key people and bodies: `name`, `role`, `stance` (−2 strongly against … +2 strongly for), `influence` (1–5). |
| `sources[]` | Places the research step should check: `name`, `url`. |
| `queries[]` | Optional search phrases for the research step. |
| `outcome` | Resolved only: `date`, `source` (URL) and optional `note`. |

## How the probability is calculated

Each **approved** evidence row adds `direction × signal weight × actor factor`
to the log-odds of the base rate, where direction is +1 (towards YES) or −1
(towards NO), and the actor factor is the actor's approved influence ÷ 3 (1 if
the actor is not in the approved register). The result is kept between 1% and
99% until an editor resolves the tracker, which sets it to 100% or 0%.

As a guide, a weight of 0.1 moves a 50% probability by about 2.5 points, 0.4 by
about 10 points, and 1.0 by about 23 points.

## Example

```json
{
  "slug": "example-act-2027",
  "title": "Example Act passed by 2027",
  "status": "active",
  "strapi": { "id": "42" },
  "question": "Will the (fictional) Example Act be signed into law by 31 December 2027?",
  "deadline": "2027-12-31",
  "resolution": {
    "yes": "The Example Act is signed into law on or before 31 December 2027.",
    "no": "The Example Act has not been signed into law by the end of 31 December 2027.",
    "source": "The official legislative record"
  },
  "base_rate": { "p": 0.2, "reasoning": "An arbitrary starting point for this example." },
  "signals": [
    { "type": "bill_introduced", "label": "Bill introduced", "weight": 0.3 },
    { "type": "committee_vote", "label": "Committee vote", "weight": 0.8 }
  ],
  "actors": [
    { "name": "Example Committee", "role": "Committee", "stance": 1, "influence": 5 }
  ],
  "sources": [{ "name": "Legislative record", "url": "https://example.org/record" }]
}
```
