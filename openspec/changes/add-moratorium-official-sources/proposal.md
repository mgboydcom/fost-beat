# Proposal

## Why

The moratorium tracker finds actions only through news searches (Google News and GDELT), so it misses actions the press doesn't cover. Every row also arrives marked `verified = no`, which leaves a growing backlog (392 rows so far) for people to check by hand. Most rows are US city and county actions. Official US sources that can be read by software are available and were tested in exploration:
- Legistar council agendas: Charlotte returned its full moratorium history with no key.
- Open States for state bills.
- GovInfo and Congress.gov for federal bills.

Together these can both find actions earlier and confirm the actions already in the sheet.

## What Changes

- Add a second n8n workflow, "Moratorium official sources", generated by a build script in `moratorium-tracker/n8n/` like the existing news workflow. It runs every 2 days.
- **Find:** search US official sources for data centre moratorium actions:
  - Legistar council agendas for a watch-list of US cities and counties;
  - Open States for state bills;
  - GovInfo for federal bills, with Congress.gov for each bill's latest action.

  Records found this way go through the same AI step, and new actions are added to the sheet.
- **Check:** for US rows not yet verified, look up the same place in the matching official source. Where the AI step confirms that an official record matches the row, mark the row verified.
- **Automatic verification for official sources:** a row whose action is confirmed by an official government source is set to `verified = yes` with `verified_by = official`. People set `verified_by = person` when they check a row themselves. A row that came only from news stays unverified until it is matched or checked by a person.
- **New sheet columns:** `official_source_url`, `verified_by` and `stage`. Stage is the latest official step, for example "public hearing set" or "adopted".
- **New sheet tab:** `Legistar watch-list`, a list kept by people of places and their Legistar client names. Places can be added without changing any code.
- **Map:** a dot's popup shows a link to the official record and says whether the row was verified by an official source or by a person.
- **Run report email** for the new workflow, in the same style as the news workflow: records found, rows added, rows verified, and source errors.
- **Out of scope:** non-US official sources (the Irish parliament API is a candidate for a later change), and court records (lawsuits about moratoriums are not moratorium actions).

## Capabilities

### New Capabilities
- `moratorium-tracker/official-sources`: finding moratorium actions in official government sources (Legistar watch-list, Open States, GovInfo and Congress.gov), turning them into tracker rows, and avoiding duplicates with rows that already exist.
- `moratorium-tracker/row-verification`: when a row counts as verified, how an official source verifies it automatically, the `verified_by` / `official_source_url` / `stage` fields, and how verification shows on the map.

### Modified Capabilities
None. No specs exist yet in this project.

## Impact

- **New files:** `moratorium-tracker/n8n/build_official_sources.py` and the generated `data-centre-moratorium-official-sources.n8n.json`.
- **Changed files:**
  - `moratorium-tracker/moratorium-map.html`, for the popup.
  - `moratorium-tracker/README.md`, for setup and sources.
  - Possibly `build_workflow.py`, for shared helpers.
- **Google Sheet:** three new columns on `Moratoriums` and a new `Legistar watch-list` tab. The news workflow appends by column name, so the new columns stay blank for its rows.
- **Credentials needed in n8n:**
  - a free Open States API key;
  - a free api.data.gov key, which works for both GovInfo and Congress.gov;
  - the existing Google Sheets, Gmail and Gemini credentials.
- **Gemini usage:** a small amount extra. Official records are filtered by keywords before any AI call.
- **No change** to the existing news workflow's behaviour.
